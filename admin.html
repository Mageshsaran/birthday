Admin password

A built-in default password works until you replace it here. A password set here overrides the default in this browser only.

Visitor password

Ask visitors for a password before the birthday site opens. This is a browser-side surprise gate, not real security — the published data and media links stay public.

Checking the visitor password…

A built-in default (welcome2026) protects a fresh deployment before you publish. Set your own password to replace it. Custom passwords save only a salted hash with the site; after changing this, publish again so the hosted site uses it.

Browser storage

Photos, videos, songs, and settings all live in this browser profile.

Calculating… —

Clearing site data, using private browsing, or running out of disk space can erase uploads. Keep a backup.

Backup & sharing

A backup contains all text, settings, and media in one file. Import it in another browser to restore everything.

Publish folder writes data/site.json and all media into a folder you choose (Chrome/Edge). Copy it together with index.html and common.js to any static host to share a link. The published site is view-only for visitors; keep editing here.

Supabase cloud

Publish the site data and media to Supabase so a hosted copy can load them from any device.

Checking cloud configuration…

The anon key in supabase-config.js is public by design. Writes require the admin account above and are enforced by Row Level Security. Never put the database password or the service_role key in this project.

Danger zone

Start completely fresh. This deletes text, media, settings, and the admin password from this browser.

About

Birthday Studio is a tiny static site: index.html, admin.html, and common.js. No server, no accounts, no external requests.

Photos and videos never leave this device unless you export a backup or publish a folder. The admin password is a local deterrent, not real authentication.
